## 1. `manifest.json`

**作用**：Chrome 扩展的入口清单，决定权限、注入时机和模块加载顺序。

主要内容：

| 字段 | 值 / 说明 |
| --- | --- |
| `manifest_version` | `3`，MV3 |
| `name` | `Maurice 标注 / 汉化` |
| `version` | `4.0` |
| `description` | 面板功能简述，注明已移除分页界面 |
| `permissions` | `activeTab`、`scripting`、`downloads`、`storage` |
| `host_permissions` | `https://lell1203.github.io/*` |
| `action.default_title` | 鼠标悬停提示“按 F1 打开面板” |
| `content_scripts[0].matches` | 只在目标站点注入 |
| `content_scripts[0].run_at` | `document_idle` |
| `content_scripts[0].js` | **18 个文件，顺序即依赖顺序** |
| `background.service_worker` | `background.js` |

`content_scripts[0].js` 的顺序：

1. `src/constants.js`
2. `src/html.js`
3. `src/dom-utils.js`
4. `src/storage.js`
5. `src/page-registry.js`
6. `src/pattern-rules.js`
7. `src/dictionary.js`
8. `src/translator.js`
9. `src/extractor.js`
10. `src/badge-layer.js`
11. `src/finder.js`
12. `src/export-builders.js`
13. `src/transfer.js`
14. `src/exporters.js`
15. `src/app.js`
16. `src/panel-template.js`
17. `src/panel.js`
18. `content.js`

关键点：

- 前面的模块先注册工厂，`content.js` 最后统一装配；
- `background.js` 会通过 `chrome.runtime.getManifest()` 读取这份列表，所以**新增模块只需要改这里**，不用再改 background；
- `downloads` 权限是旧版保留的，目前下载走 `<a download>`，没有直接调用 `chrome.downloads`；
- 要支持别的站点，改 `matches` 和 `host_permissions` 两处。

## 2. `background.js`

**作用**：扩展图标点击的后台转发器，不参与页面逻辑。

流程：

```
用户点扩展图标
  → chrome.action.onClicked
  → 先尝试 chrome.tabs.sendMessage(tabId, { action: 'toggle' })
      ├─ 成功：content.js 收到消息，开关面板
      └─ 失败：说明页面还没注入
           → chrome.runtime.getManifest() 取 content_scripts[0].js
           → chrome.scripting.executeScript({ files })
           → 150ms 后再发一次 toggle
```

关键函数：

- `getContentScriptFiles()`：从 manifest 读取需要补注入的文件，避免维护第二份清单；
- `TOGGLE_MESSAGE = 'toggle'`：与 `constants.TOGGLE_MESSAGE` 对应。

注意：

- 只在 `https://lell1203.github.io/*` 有权限；`chrome://`、扩展商店等页面注入会失败，代码里静默忽略；
- 补注入时按 manifest 顺序执行，所以 `content.js` 一定最后跑。

## 3. `content.js`

**作用**：启动入口，只做“依赖装配 + 事件绑定”，不含业务逻辑。

结构：

1. **防重复注入**：`global.__mauriceAnnoLoaded` 标记，重复执行直接 return；
2. **模块完整性检查**：`REQUIRED_MODULES` 列出 17 个模块，缺一个就打印错误并停止；
3. **创建服务**：
   - 基础：`domUtils`、`transfer`、`store`、`pageRegistry`、`dictionary`、`patternEngine`
   - 业务：`translator`、`extractor`、`badges`、`finder`、`builders`、`exporters`
   - 应用：`app`
   - 界面：`panel`
4. **共享会话对象**：`const session = { pageId: null }`，`translator` 和 `app` 都通过它读取当前页号；
5. **启动**：`app.init()`，成功后 `panel.update()`，失败只打日志；
6. **快捷键**：捕获阶段监听 `F1`，阻止默认行为并 `panel.toggle()`；
7. **扩展消息**：监听 `{ action: 'toggle' }`，点图标时开关面板。

装配顺序不能乱：后面的工厂依赖前面创建好的实例（例如 `translator` 需要 `dictionary`，`exporters` 需要 `translator`）。

## 4. `src/constants.js`

**作用**：全局唯一配置源。其它模块只读这里，避免同一条规则写多份。

导出：`Maurice.constants`（`Object.freeze`）。

内容分组：

| 分组 | 内容 |
| --- | --- |
| 存储 | `STORAGE_KEYS = ['pageIdMap','pageCounter','pages','dicts','activeDicts']` |
| 扫描 | `SKIP_TAGS`、`DOC_CLASS_RE`、`EDITOR_CONTAINER_RE`、`KOREAN_RE`、`ENGLISH_RE`、`INVISIBLE_CHARS_RE` |
| 数据格式 | `CUSTOM_DICT_NAME='custom'`、`CUSTOM_DICT_DESCRIPTION`、`DICT_FORMAT='maurice-dict'`、`DICT_FORMAT_VERSION='1.0'` |
| 导出文件名 | `EXPORT_FILENAMES`：文本对照保留英文名；待翻译 / 合并 / 单个词库用中文名 |
| 编号 | `ID_PATTERN=/^(P\d+)-(\d+)$/i`、`PAGE_ID_PREFIX='P'`、`TEXT_ID_SEPARATOR='-'` |
| 消息 | `TOGGLE_MESSAGE='toggle'` |
| 界面 | 面板宽度、三级 z-index、高亮时长 4 秒、矩形最小尺寸、祖先查找深度 |
| 颜色 | `COLORS.badgeCode`、`badgeUi`、`badgeActive`、`highlightFill`、`highlightOutline` |

修改建议：

- 改站点选择器 / 代码区判断 → 改这里；
- 改颜色、高亮时长 → 改这里；
- 新增模块常量时，测试会检查代码里引用的 `constants.*` 是否真实存在。

## 5. `src/html.js`

**作用**：HTML 转义，防止页面文本 / 词库名 / 用户输入被当成 HTML 执行。

导出：`Maurice.html = { escapeHtml, escapeAttr }`。

- `escapeHtml(value)`：转义 `& < > " '`；
- `escapeAttr(value)`：属性值转义，规则相同，单独命名以示语义；
- 面板里所有拼进 `innerHTML` 的动态字符串都必须经过它。

## 6. `src/dom-utils.js`

**作用**：所有“读 DOM”的判断集中在这里，提取器和翻译器共用，避免两套规则不一致。

导出：`Maurice.createDomUtils({ constants })`。

返回的方法：

| 方法 | 说明 |
| --- | --- |
| `resetVisibilityCache()` | 每次整页扫描前清空可见性缓存 |
| `isVisible(node)` | 父元素是否有尺寸、没被 `display/visibility/opacity` 隐藏；优先用 `checkVisibility`，老浏览器手动向上查 |
| `cleanText(raw)` | 去掉零宽字符、软连字符并 `trim()` |
| `getTextType(node)` | 返回 `'ui'` 或 `'code'`：先看有没有文档容器 class，再看是否在编辑器 / `TEXTAREA` / `contentEditable` 中；`pre/code` 默认放行 |
| `getNodeRects(node)` | 用 `Range` 取文本节点的所有矩形 |
| `getValidRects(node)` | 过滤掉小于 4×6 的矩形 |
| `getFirstRect(node)` | 取第一个有效矩形，用于贴徽标 |
| `createTextWalker(root)` | 只遍历可处理文本节点的 TreeWalker，跳过 `SCRIPT/STYLE` 等 |
| `forEachTextNode(root, visit)` | 上面的便捷封装，回调 `(node, cleanText)` |

性能点：

- 可见性按父元素缓存，一次扫描只算一次；
- 代码区判断有最大祖先深度限制（30 层），避免极端 DOM 拖慢。

## 7. `src/storage.js`

**作用**：`chrome.storage.local` 的唯一读写入口，其它模块不直接碰 chrome API。

导出：`Maurice.createStore({ constants, storageArea? })`。

内部状态 `state`（保持同一对象引用）：

```js
{
  pageIdMap: {},    // URL key → 'P1'
  pageCounter: 0,   // 已分配的最大页号数字
  pages: {},        // P1 → { url, title, extractedAt, texts: [...] }
  dicts: {},        // 词库名 → { name, description, global, perPage }
  activeDicts: []   // 启用中的词库名
}
```

方法：

| 方法 | 说明 |
| --- | --- |
| `load()` | 从存储重新读取全部键；多标签页共享数据，操作前读一次最稳 |
| `saveAll()` | 写全部五个键 |
| `saveDicts()` | 只写 `dicts` + `activeDicts` |
| `savePageIndex()` | 只写 `pageIdMap` + `pageCounter` |
| `savePages()` | 只写 `pages` |

兼容性：

- 键名和数据结构与旧版 3.5 完全一致；
- 旧词库、旧页面快照不需要迁移；
- `storageArea` 可注入，测试里用内存假存储替代。

## 8. `src/page-registry.js`

**作用**：内部页号注册表。**它不产生任何界面**，只保证编号稳定和按页数据可用。

导出：`Maurice.createPageRegistry({ store, constants, getUrlKey? })`。

方法：

| 方法 | 说明 |
| --- | --- |
| `urlKey()` | 默认 `location.pathname + search + hash` |
| `getCurrentPageId()` | 当前 URL 已分配的页号，没有返回 `null` |
| `resolvePageId()` | 有就复用，没有就分配 `P<next>` 并落盘 |
| `nextPageNumber()` | 扫描 `pageIdMap` 和 `pages` 里的 `P?` 取最大值 +1，防止 `pageCounter` 落后撞号 |
| `recordPage(pageId, snapshot)` | 保存 `{ url, title, extractedAt, texts }` |
| `listPageIds()` | 按数字排序返回页号 |
| `getPage(pageId)` | 取页面快照 |

分页界面已移除，但这一层保留的原因：

1. 编号仍是 `P?-??`；
2. 同一 URL 刷新后编号不变；
3. “存当前页”词库需要页号；
4. 跨页查找 / 导出需要页面快照。

## 9. `src/pattern-rules.js`

**作用**：把带数字的词条编译成正则，处理“动态数字”文本。纯函数，不碰 DOM / 存储。

导出：`Maurice.createPatternEngine()`。

支持的词条写法：

```jsonc
{
  "{d}일차": "第{d}天",   // 显式占位符
  "Day 3": "第3天"        // 原文自动抓数字
}
```

对应匹配：

- `7일차` → `第7天`
- `Day 42` → `第42天`

方法：

| 方法 | 说明 |
| --- | --- |
| `compileRule(original, translation)` | 单条编译，返回 `{ regex, template }` 或 `null` |
| `compile({ dicts, activeDicts, pageId })` | 收集所有启用词库的全局规则 + 本页规则，排序后返回数组 |
| `expand(rule, match)` | 用捕获组填充 `$1`、`$2`…… |
| `escapeRegExp(text)` | 正则元字符转义 |

规则优先级：

1. 正则源码越长越优先（更具体的规则先匹配）；
2. 同样长度时，`priority` 大者优先，即**本页规则 > 全局规则**。

注意：模板填充用 `split/join`，避免译文里的 `$&`、`$1` 被 `String.replace` 二次解释。

## 10. `src/dictionary.js`

**作用**：词库仓库。管理词库数据、启用状态、精确匹配、导入 / 导出 payload。

导出：`Maurice.createDictionary({ store, constants })`。

数据模型：

```js
dicts[name] = {
  name, description, version, author,
  global:  { 原文: 译文 },
  perPage: { P1: { 原文: 译文 } }
}
```

方法：

| 方法 | 说明 |
| --- | --- |
| `init()` | 确保 `custom` 词库存在并启用，然后 `saveAll()` |
| `all()` / `activeNames()` / `get(name)` | 读取词库与启用列表 |
| `lookupExact(original, pageId)` | 精确匹配：本页词条优先，其次全局；后启用的词库优先 |
| `saveTranslation(original, translated, scope, pageId)` | 写 `custom` 词库；译文为空表示删除；`scope` 为 `global` / `page` |
| `importData(data)` | 校验 `name`，写入词库并自动启用；返回 `{ key, isOverwrite }` |
| `setEnabled(name, enabled)` | 勾选 / 取消启用 |
| `remove(name)` | 删除词库，`custom` 受保护返回 `false` |
| `countWords(dict)` | 全局 + 各页词条总数 |
| `list()` | 面板列表用的只读视图（名称、描述、数量、是否启用、能否删除） |
| `mergeEnabled()` | 合并所有启用词库 |
| `toPayload(name)` | 单个词库的导出对象 |

注意：

- 这里只做**精确匹配**；带数字的动态规则由 `pattern-rules` 负责；
- 导入文件读取 / JSON 解析在 `transfer.js`，这里只接收对象；
- `custom` 词库不能删，避免用户误删面板里随手存的翻译。

## 11. `src/translator.js`

**作用**：把词库应用到页面：查词、替换文本节点、监听动态内容。

导出：`Maurice.createTranslator({ dictionary, patternEngine, domUtils, getPageId })`。

内部状态：

- `rules`：当前页编译后的动态规则；
- `replacedNodes`：`WeakSet`，记录已处理节点，防止观察器反复套娃；
- `observer`：`MutationObserver` 实例。

方法：

| 方法 | 说明 |
| --- | --- |
| `rebuild(pageId)` | 重新编译规则；词库变化 / 切页后调用 |
| `lookup(original, pageId)` | 先精确匹配，再按规则匹配；没有返回 `null` |
| `replaceNode(node, pageId)` | 替换单个文本节点，保留前后空白；代码区跳过并标记 |
| `replaceAll(root, pageId)` | 遍历并替换，返回替换数量 |
| `apply(pageId)` | 全页替换，等价 `replaceAll(document.body)` |
| `startObserver({ onChanged })` | 监听新增节点，动态插入的终端日志也会翻译；有替换时回调 |
| `stopObserver()` | 断开观察器 |
| `getRuleCount()` | 当前规则数量（调试 / 测试用） |

细节：

- 文本先经 `domUtils.cleanText` 清洗，再查词；
- `replacedNodes` 防止同一节点被重复处理；代价是译文更新后需要刷新页面才能重翻；
- 观察器只处理 `childList` 新增节点，不监听文本内容修改。

## 12. `src/extractor.js`

**作用**：扫描页面，把含韩文 / 英文的文本节点编号并收集成标注列表。

导出：`Maurice.createExtractor({ domUtils, constants })`。

方法：

| 方法 | 说明 |
| --- | --- |
| `extractAll(pageId)` | 返回 `{ annotations, stats }` |
| `toStoredEntries(annotations)` | 去掉 DOM 引用，转成可写入存储的纯数据 |

`extractAll` 流程：

1. `domUtils.resetVisibilityCache()`；
2. 遍历 `document.body` 下所有文本节点；
3. `cleanText` 后为空则跳过；
4. 不含韩文也不含英文则跳过；
5. `textId++`，生成 `id = pageId + '-' + textId`；
6. 记录 `type`（`ui` / `code`）、`text`、`node`、`visible`；
7. 统计 `{ total, visible, hidden }`。

注意：

- 隐藏文本也会提取，只是没有几何位置、不画徽标；
- 文本序号每次提取从 1 重新数，所以 ID 的稳定性依赖“同一页面同一时刻的 DOM 顺序”。

## 13. `src/badge-layer.js`

**作用**：在页面上画 `P?-??` 徽标，以及点击 / 查找时的高亮框。

导出：`Maurice.createBadgeLayer({ domUtils, constants, onBadgeClick })`。

结构：

- 覆盖层：`position: fixed; inset: 0; pointer-events: none; z-index: 2147483646`；
- 每个徽标：绝对定位、`pointer-events: auto`、点击高亮并回调；
- 高亮框：`position: absolute`，坐标叠加 `scrollX/scrollY`，`z-index: 2147483645`。

方法：

| 方法 | 说明 |
| --- | --- |
| `render(list?)` | 重画徽标；省略参数时沿用上次标注列表；不可见节点跳过 |
| `clear()` | 移除覆盖层，清空徽标 |
| `reposition()` | 滚动 / 缩放 / 文字变宽后重新贴徽标 |
| `highlight(node)` | 高亮并滚动到节点；隐藏节点返回 `false` |
| `clearHighlight()` | 清除高亮和定时器，恢复徽标颜色 |
| `show()` / `hide()` / `isVisible()` | 标注总开关 |

细节：

- 颜色：代码区红色 `#e11d48`，普通界面蓝色 `#2563eb`，被选中时黄色 `#f59e0b`；
- 高亮 4 秒后自动清除（`constants.HIGHLIGHT_DURATION_MS`）；
- 覆盖层是 fixed，徽标坐标使用视口坐标，不叠加滚动偏移；
- 滚动 / resize 监听只注册一次，避免重复绑定。

## 14. `src/finder.js`

**作用**：按 `P1-42` 这样的编号查词，返回给面板显示的消息。

导出：`Maurice.createFinder({ store, constants, badges, translator? })`。

方法：

| 方法 | 说明 |
| --- | --- |
| `parse(query)` | 解析编号，返回 `{ pageId, textId }` 或 `null` |
| `find(query, { pageId, getAnnotations })` | 查当前页 / 已抓取的其他页 |
| `translationFor(annotation, pageId)` | 查已有译文，用于回填输入框 |

查找结果类型：

- `current`：当前页找到且能高亮；
- `hidden`：当前页找到但文本隐藏，无法高亮，提示可直接填翻译；
- `other`：编号属于其他页，返回标题 / URL / 原文；
- `ok:false`：格式错误、当前页没有、页号没抓过、条目不存在。

注意：它只负责“查 + 返回消息”，不直接写面板 DOM。

## 15. `src/export-builders.js`

**作用**：把数据拼成导出内容。**纯函数**，不下载、不读存储，所以能直接用 Node 测试。

导出：`Maurice.createExportBuilders({ constants })`。

方法：

| 方法 | 输出 |
| --- | --- |
| `sortPageIds(pages)` | 按 `P` 后的数字排序 |
| `buildPendingPayload({ pages, lookup })` | 未翻译词库对象：`global` 里是待填译文，`_sourceIds` 记录每个原文出现在哪些编号 |
| `buildTextsJson({ pages, lookup })` | JSON 数组字符串，字段：`id/pageId/textId/type/text/translation` |
| `buildTextsTsv({ pages, lookup })` | TSV 字符串，表头 `id\ttype\ttext\ttranslation` |
| `buildMergedPayload({ dicts, activeNames })` | 合并所有启用词库的 payload |

规则：

- 未翻译列表跳过 `type === 'code'` 的条目；
- 已有译文的条目不再进入未翻译列表；
- 合并时后启用的词库覆盖先启用的；
- TSV 里的制表符替换为空格，避免列错位。

## 16. `src/transfer.js`

**作用**：文件进出的细节封装：触发下载、读取用户选的 JSON。

导出：`Maurice.createTransfer({ documentRef?, BlobCtor?, urlApi? })`。

方法：

| 方法 | 说明 |
| --- | --- |

| `readJsonFile(file)` | `file.text()` + `JSON.parse`，解析失败抛出“这不是个合法的 JSON 文件” |

## 17. `src/exporters.js`

**作用**：导出流程编排：读存储 → 调 builders → 交给 transfer 下载。

导出：`Maurice.createExporters({ store, dictionary, translator, transfer, builders, constants })`。

方法：

| 方法 | 下载文件 | 能否再导入 |
| --- | --- | --- |
| `exportAll('json')` | `maurice_texts.json` | 否，文本对照数据 |

## 18. `src/app.js`

**作用**：应用层。把各服务组合成面板可以直接调用的动作，持有“当前页号 / 当前提取结果”这份会话状态。

导出：`Maurice.createApp({ session, store, pageRegistry, dictionary, translator, extractor, badges, finder, exporters, transfer })`。

初始化 `init()`（幂等）：

```
store.load()
→ dictionary.init()
→ pageRegistry.resolvePageId()
→ translator.rebuild()
→ translator.apply()          先把已有词库应用到页面
→ extractor.extractAll()      抓一遍文本备用
→ translator.startObserver()  监听动态内容
```

动作：

| 方法 | 说明 | 返回 |
| --- | --- | --- |
| `extract()` | 提取 + 保存页面快照 + 重画徽标 | 提取结果文字 |
| `applyAll()` | 重新翻译全页 | 替换数量文字 |
| `saveTranslation({source,target,scope})` | 存 `custom` 词库并立即应用 | 结果文字 |
| `deleteTranslation(source)` | 从全局 / 本页删除该原文 | 结果文字 |
| `toggleDict(name, enabled)` | 启用 / 停用词库并重新应用 | 结果文字 |
| `deleteDict(name)` | 删除词库（custom 受保护） | 结果文字 |
| `importFile(file)` | 读 JSON、导入词库、立即应用 | 结果文字 |
| `find(query)` | 查编号，回填原文 / 译文 | `{ message, source?, translation? }` |
| `setBadgesVisible(show)` | 显示 / 取消标注 | 当前可见状态 |
| `exportAll(kind)` / `exportPending()` / `exportMerged()` / `exportDict(name)` | 导出 | 已导出文件名文字 |
| `getDicts()` | 面板词库列表 | 数组 |
| `getPageId()` / `getAnnotations()` | 只读会话状态 | — |

错误处理：动作抛 `Error`，由面板的 `run()` 统一捕获并显示“出错：…”，应用层不直接操作 DOM。

## 19. `src/panel-template.js`

**作用**：面板的 HTML 模板。纯字符串函数，不绑定事件、不查 DOM。

导出：`Maurice.panelTemplate({ constants })`。

面板分区：

1. 标题栏：标题 + 关闭按钮 `data-act="close"`；
2. 主操作：`提取并保存`；
3. 标注控制：`显示标注` / `取消标注` / `应用翻译`；
4. 查词：`data-el="q"` + `查找`；

## 20. `src/panel.js`

**作用**：面板视图层。建 DOM、绑事件、调用 `app`、展示结果。

导出：`Maurice.createPanel({ app, constants, html, template })`。

内部流程：

- `build()`：首次打开时创建容器、插入模板、绑定事件；
- `run(action)`：统一 `try/catch`，成功显示返回消息，失败显示“出错：…”，最后 `update()`；
- `bindEvents()`：事件委托处理所有按钮、词库勾选、文件选择、回车；
- `renderDictList()`：用 `app.getDicts()` 生成词库行，所有动态字符串走 `html.escape*`；
- `update()`：刷新标注按钮透明度、词库列表；
- `setResult(text)`：写结果区；
- `show()` / `hide()` / `toggle()`：面板显隐。

事件映射（`data-act`）：

`close`、`extract`、`show-badges`、`hide-badges`、`apply-all`、`find`、`save-global`、`save-page`、`del-trans`、`import-dict`、`export-all-dicts`、`export-pending`、`export-json`、`export-tsv`。

另外：

- `[data-dict-export]` / `[data-dict-del]` 是词库行内按钮，优先于通用按钮处理；
- `[data-dict-toggle]` 改变时调用 `app.toggleDict`；
- 文件输入 `change` 后调用 `app.importFile`，并在 `finally` 里清空，允许重复选同一个文件。

## 27. 数据流

### 启动

```
content.js
  → 创建服务
  → app.init()
      → storage.load()
      → dictionary.init()          确保 custom 词库
      → page-registry.resolvePageId()
      → translator.rebuild/apply   把已有词库写到页面
      → extractor.extractAll()     收集当前文本备用
      → translator.startObserver() 监听动态内容
```

### 提取

```
点“提取并保存”
  → storage.load()
  → page-registry.resolvePageId()
  → extractor.extractAll(pageId)
  → page-registry.recordPage()     保存快照
  → badge-layer.render()           画 P?-?? 徽标
  → 面板显示“共提取 N 条”
```

### 翻译

```
词库变化（保存 / 导入 / 勾选）
  → dictionary 写入 storage
  → translator.rebuild()
  → translator.apply()
      → 遍历文本节点
      → dictionary.lookupExact()
      → pattern-rules 匹配动态数字
      → 替换 textContent，保留空白
```

### 导出

```
exporters.export*()
  → storage.load()
  → export-builders 拼内容
  → transfer.downloadFile()
  → 浏览器下载 JSON / TSV
```

## 29. 边界约定（避免再次耦合）

1. **DOM 只出现在 `dom-utils`、`extractor`、`translator`、`badge-layer`、`panel`、`panel-template`、`content`、`transfer`**；`app` 以下不拼 HTML。
2. **chrome.storage 只出现在 `storage.js`**；其它模块通过 `store`。
3. **业务消息只在 `app.js` 生成**；`panel.js` 只负责显示。
4. **导出内容构造是纯函数**，不要在里面下载或读存储。
5. **新增模块必须登记到 manifest 的 `js` 数组**，加载顺序即依赖顺序；`background` 会自动读取，无需重复登记。
6. **页面文本拼 HTML 必须转义**（`html.js`）。
