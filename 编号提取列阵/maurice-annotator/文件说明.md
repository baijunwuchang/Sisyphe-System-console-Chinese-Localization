## 1. `manifest.json`

**作用**：Chrome 扩展的入口清单，决定权限、注入时机和模块加载顺序。

主要内容：

| 字段 | 值 / 说明 |
| --- | --- |
| `manifest_version` | `3`，MV3 |
| `name` | `Maurice 标注 / 汉化` |
| `version` | `4.0` |
| `description` | 面板功能简述，注明已移除分页界面 |
| `permissions` | `activeTab`、`scripting`、`downloads`、`storage` |
| `host_permissions` | `https://lell1203.github.io/*`、`http://47.80.59.80/*` |
| `action.default_title` | 鼠标悬停提示“按 Alt+M 打开面板” |
| `content_scripts[0].matches` | 只在目标站点注入 |
| `content_scripts[0].run_at` | `document_idle` |
| `content_scripts[0].js` | **21 个文件，顺序即依赖顺序** |
| `background.service_worker` | `background.js` |

`content_scripts[0].js` 的顺序：

1. `src/constants.js`
2. `src/html.js`
3. `src/dom-utils.js`
4. `src/storage.js`
5. `src/page-registry.js`
6. `src/pattern-rules.js`
7. `src/dictionary.js`
8. `src/translator.js`
9. `src/extractor.js`
10. `src/badge-layer.js`
11. `src/selection.js`
12. `src/finder.js`
13. `src/export-builders.js`
14. `src/text-table.js`
15. `src/server-api.js`
16. `src/transfer.js`
17. `src/exporters.js`
18. `src/app.js`
19. `src/panel-template.js`
20. `src/panel.js`
21. `content.js`

关键点：

- 前面的模块先注册工厂，`content.js` 最后统一装配；
- `background.js` 会通过 `chrome.runtime.getManifest()` 读取这份列表，所以**新增模块只需要改这里**，不用再改 background；
- `downloads` 权限是旧版保留的，目前下载走 `<a download>`，没有直接调用 `chrome.downloads`；
- 要支持别的站点，改 `matches` 和 `host_permissions` 两处。

## 2. `background.js`

**作用**：扩展图标点击的后台转发器，不参与页面逻辑。

流程：

```
用户点扩展图标
  → chrome.action.onClicked
  → 先尝试 chrome.tabs.sendMessage(tabId, { action: 'toggle' })
      ├─ 成功：content.js 收到消息，开关面板
      └─ 失败：说明页面还没注入
           → chrome.runtime.getManifest() 取 content_scripts[0].js
           → chrome.scripting.executeScript({ files })
           → 150ms 后再发一次 toggle
```

关键函数：

- `getContentScriptFiles()`：从 manifest 读取需要补注入的文件，避免维护第二份清单；
- `TOGGLE_MESSAGE = 'toggle'`：与 `constants.TOGGLE_MESSAGE` 对应。

注意：

- content script 只在 `https://lell1203.github.io/*` 注入；`chrome://`、扩展商店等页面注入会失败，代码里静默忽略；
- `host_permissions` 同时包含 `http://47.80.59.80/*`，供 background 请求共享服务器；
- 补注入时按 manifest 顺序执行，所以 `content.js` 一定最后跑。

### 共享服务器代理

页面是 HTTPS，而 API 是 HTTP。为避免混合内容限制，所有服务器请求走 background：

```
content/server-api.js
  → chrome.runtime.sendMessage({type:'maurice-api', method, path, body})
  → background.js handleServerRequest()
  → fetch(http://47.80.59.80/maurice-api.php?...)
  → sendResponse({ok, data})
```

- 只允许 `GET` / `POST`，路径必须以 `?` 开头；
- 15 秒超时；
- `host_permissions` 中已声明 `http://47.80.59.80/*`；
- 服务器返回非 2xx 或 `ok:false` 时，统一转成 `Error` 交给面板显示。

## 3. `content.js`

**作用**：启动入口，只做“依赖装配 + 事件绑定”，不含业务逻辑。

结构：

1. **防重复注入**：`global.__mauriceAnnoLoaded` 标记，重复执行直接 return；
2. **模块完整性检查**：`REQUIRED_MODULES` 列出 20 个模块，缺一个就打印错误并停止；
3. **创建服务**：
   - 基础：`domUtils`、`transfer`、`store`、`pageRegistry`、`dictionary`、`patternEngine`
   - 业务：`translator`、`extractor`、`badges`、`selection`、`finder`、`builders`、`textTable`、`serverApi`、`exporters`
   - 应用：`app`
   - 界面：`panel`
4. **共享会话对象**：`const session = { pageId: null }`，`translator` 和 `app` 都通过它读取当前页号；
5. **启动**：`app.init()`，成功后 `panel.update()`，失败只打日志；
6. **快捷键**：捕获阶段监听 `Alt+M`（主）与 `F1`（兼容尝试），阻止默认行为并 `panel.toggle()`；F1 可能被浏览器帮助页占用，面板里也有提示；
7. **扩展消息**：监听 `{ action: 'toggle' }`，点图标时开关面板。

装配顺序不能乱：后面的工厂依赖前面创建好的实例（例如 `translator` 需要 `dictionary`，`exporters` 需要 `translator`）。

## 6. `src/dom-utils.js`

**作用**：所有“读 DOM”的判断集中在这里，提取器和翻译器共用，避免两套规则不一致。

导出：`Maurice.createDomUtils({ constants })`。

返回的方法：

| 方法 | 说明 |
| --- | --- |
| `resetVisibilityCache()` | 每次整页扫描前清空可见性缓存 |
| `isVisible(node)` | 父元素是否有尺寸、没被 `display/visibility/opacity` 隐藏；优先用 `checkVisibility`，老浏览器手动向上查 |
| `cleanText(raw)` | 去掉零宽字符、软连字符并 `trim()` |
| `getTextType(node)` | 返回 `'ui'` 或 `'code'`：先看有没有文档容器 class，再看是否在编辑器 / `TEXTAREA` / `contentEditable` 中；`pre/code` 默认放行 |
| `getNodeRects(node)` | 用 `Range` 取文本节点的所有矩形 |
| `getValidRects(node)` | 过滤掉小于 4×6 的矩形 |
| `getFirstRect(node)` | 取第一个有效矩形，用于贴徽标 |
| `createTextWalker(root)` | 只遍历可处理文本节点的 TreeWalker，跳过 `SCRIPT/STYLE` 等 |
| `forEachTextNode(root, visit)` | 上面的便捷封装，回调 `(node, cleanText)` |

性能点：

- 可见性按父元素缓存，一次扫描只算一次；
- 代码区判断有最大祖先深度限制（30 层），避免极端 DOM 拖慢。

## 7. `src/storage.js`

**作用**：`chrome.storage.local` 的唯一读写入口，其它模块不直接碰 chrome API。

导出：`Maurice.createStore({ constants, storageArea? })`。

内部状态 `state`（保持同一对象引用）：

```js
{
  pageIdMap: {},    // URL key → 'P1'
  pageCounter: 0,   // 已分配的最大页号数字
  pages: {},        // P1 → { url, title, extractedAt, texts: [...],
                    //         textIdMap: { 稳定键: textId }, nextTextId }
  dicts: {},        // 词库名 → { name, description, global, perPage }
  activeDicts: [],  // 启用中的词库名
  clientId: ''      // 共享服务器的本机用户标识（随机 UUID）
}
```

方法：

| 方法 | 说明 |
| --- | --- |
| `load()` | 从存储重新读取全部键；多标签页共享数据，操作前读一次最稳 |
| `saveAll()` | 写全部六个键 |
| `saveDicts()` | 只写 `dicts` + `activeDicts` |
| `savePageIndex()` | 只写 `pageIdMap` + `pageCounter` |
| `savePages()` | 只写 `pages` |
| `saveClientId()` | 只写 `clientId` |

兼容性：

- 键名与旧版一致；页面快照新增 `textIdMap` / `nextTextId` 用于稳定编号；
- 旧词库、旧页面快照不需要手动迁移（首次使用会自动从 `texts` 的 `textId` 生成映射）；
- `storageArea` 可注入，测试里用内存假存储替代。

## 8. `src/page-registry.js`

**作用**：内部页号注册表。**它不产生任何界面**，只保证编号稳定和按页数据可用。

导出：`Maurice.createPageRegistry({ store, constants, getUrlKey? })`。

方法：

| 方法 | 说明 |
| --- | --- |
| `urlKey()` | 默认 `location.pathname + search + hash` |
| `getCurrentPageId()` | 当前 URL 已分配的页号，没有返回 `null` |
| `resolvePageId()` | 有就复用，没有就分配 `P<next>` 并落盘 |
| `nextPageNumber()` | 扫描 `pageIdMap` 和 `pages` 里的 `P?` 取最大值 +1，防止 `pageCounter` 落后撞号 |
| `ensureTextIdState(pageId)` | 确保页面有 `textIdMap` / `nextTextId`；旧快照按 `textId` 迁移 |
| `createIdAllocator(pageId)` | 创建一次提取的编号分配器；已有文本复用编号，新文本分配新号 |
| `recordPage(pageId, snapshot)` | 保存 `{ url, title, extractedAt, texts }`，并保留 `textIdMap` / `nextTextId` |
| `listPageIds()` | 按数字排序返回页号 |
| `getPage(pageId)` | 取页面快照 |

稳定编号的键：

```
文本类型 + "\0" + 原文 + "\0#" + 同文出现序号
```

- 不同原文永远不会共用编号；
- 同一文本第二次及以后出现时，用序号区分；
- 再次提取时，键相同就复用 `textIdMap` 里的编号；
- 新出现的文本只从 `nextTextId` 继续分配，不会重排已有编号；
- 旧快照如果已有重复 `textId`，迁移时只保留第一个占用者，其余重复项分配新号（自动修复历史冲突）。

分页界面已移除，但这一层保留的原因：

1. 编号仍是 `P?-??`；
2. 同一 URL 刷新后编号不变；
3. “存当前页”词库需要页号；
4. 跨页查找 / 导出需要页面快照。

## 9. `src/pattern-rules.js`

**作用**：把带数字的词条编译成正则，处理“动态数字”文本。纯函数，不碰 DOM / 存储。

导出：`Maurice.createPatternEngine()`。

支持的词条写法：

```jsonc
{
  "{d}일차": "第{d}天",   // 显式占位符
  "Day 3": "第3天"        // 原文自动抓数字
}
```

对应匹配：

- `7일차` → `第7天`
- `Day 42` → `第42天`

方法：

| 方法 | 说明 |
| --- | --- |
| `compileRule(original, translation)` | 单条编译，返回 `{ regex, template }` 或 `null` |
| `compile({ dicts, activeDicts, pageId })` | 收集所有启用词库的全局规则 + 本页规则，排序后返回数组 |
| `expand(rule, match)` | 用捕获组填充 `$1`、`$2`…… |
| `escapeRegExp(text)` | 正则元字符转义 |

规则优先级：

1. 正则源码越长越优先（更具体的规则先匹配）；
2. 同样长度时，`priority` 大者优先，即**本页规则 > 全局规则**。

注意：模板填充用 `split/join`，避免译文里的 `$&`、`$1` 被 `String.replace` 二次解释。

## 10. `src/dictionary.js`

**作用**：词库仓库。管理词库数据、启用状态、精确匹配、导入 / 导出 payload。

导出：`Maurice.createDictionary({ store, constants })`。

数据模型：

```js
dicts[name] = {
  name, description, version, author,
  title, serverCode,          // 可选：服务器文件标题 / 编号
  global:  { 原文: 译文 },
  perPage: { P1: { 原文: 译文 } }
}
```

方法：

| 方法 | 说明 |
| --- | --- |
| `init()` | 确保 `custom` 词库存在并启用，然后 `saveAll()` |
| `all()` / `activeNames()` / `get(name)` | 读取词库与启用列表 |
| `lookupExact(original, pageId)` | 精确匹配：本页词条优先，其次全局；后启用的词库优先 |
| `saveTranslation(original, translated, scope, pageId)` | 写 `custom` 词库；译文为空表示删除；`scope` 为 `global` / `page` |
| `importData(data)` | 校验 `name`，写入词库并自动启用；返回 `{ key, isOverwrite }` |
| `installServerFile({code,title,description,content,updatedAt,activate})` | 安装/更新服务器词库到固定 key `server-<编号>`；记录 `serverUpdatedAt`，默认不启用 |
| `attachServerCode(name, code, title)` | 给本地词库记录已上传的服务器编号 |
| `detachServerCode(name)` / `detachServerCodeByCode(code)` | 解除服务器编号关联 |
| `findByServerCode(code)` | 按编号找本地词库 |
| `setEnabled(name, enabled)` | 勾选 / 取消启用 |
| `setOnly(name)` | 只保留一个启用词库（面板“加载”按钮用） |
| `applyTable(rows)` | 导入可编辑对照表：写入 `导入对照表` 词库、生成全局/本页译文、置为最高优先级；返回 `{ updated, skipped, total, dictName }` |
| `remove(name)` | 删除词库，`custom` 受保护返回 `false` |
| `countWords(dict)` | 去重后的词条数（全局 + 各页） |
| `list()` | 面板列表用的只读视图（名称、描述、数量、是否启用、能否删除） |
| `mergeEnabled()` | 合并所有启用词库 |
| `toPayload(name)` | 单个词库的导出对象 |

注意：

- 这里只做**精确匹配**；带数字的动态规则由 `pattern-rules` 负责；
- `custom` 初始化时放在启用列表**最前面**（优先级最低），后导入的词库可以覆盖它；
- 对照表导入会创建/更新 `导入对照表` 词库，并放到启用列表最后（最高优先级）；
- 导入文件读取 / JSON 解析在 `transfer.js`，对照表解析在 `text-table.js`；
- `custom` 词库不能删，避免用户误删面板里随手存的翻译。

## 11. `src/translator.js`

**作用**：把词库应用到页面：查词、替换文本节点、监听动态内容。

导出：`Maurice.createTranslator({ dictionary, patternEngine, domUtils, getPageId })`。

内部状态：

- `rules`：当前页编译后的动态规则；
- `nodeStates`：`Map<Text, { original, applied, rendered }>`，记录每个被翻译节点的初始原文和当前译文，用于原地更新 / 恢复；
- `observer`：`MutationObserver` 实例。

方法：

| 方法 | 说明 |
| --- | --- |
| `rebuild(pageId)` | 重新编译规则；词库变化 / 切页后调用 |
| `lookup(original, pageId)` | 先精确匹配，再按规则匹配；没有返回 `null` |
| `replaceNode(node, pageId)` | 替换单个文本节点，保留前后空白；已有译文可更新，译文被删可恢复原文；代码区跳过 |
| `replaceAll(root, pageId)` | 遍历并替换，返回发生变化的节点数 |
| `apply(pageId)` | 全页应用，等价 `replaceAll(document.body)` |
| `clearApplied()` | 把页面上已应用的译文全部恢复成原文，返回恢复数量；词库不动 |
| `getOriginalText(node)` | 取节点原文：已翻译返回最初原文，未翻译返回当前文本；供提取器使用 |
| `startObserver({ onChanged })` | 监听新增节点，动态插入的终端日志也会翻译；有变化时回调 |
| `stopObserver()` | 断开观察器 |
| `getRuleCount()` | 当前规则数量（调试 / 测试用） |

细节：

- 文本先经 `domUtils.cleanText` 清洗，再查词；
- 节点被翻译后，再导入新词库会读取 `nodeStates.original` 重新查词并**原地更新**，不需要刷新；
- 如果页面自己改过节点文本，会以当前文本作为新原文，避免用过期缓存覆盖；
- `clearApplied()` 会恢复原文并清掉节点状态，之后“应用翻译”可以重新建立；
- 观察器只处理 `childList` 新增节点，不监听文本内容修改。

## 12. `src/extractor.js`

**作用**：扫描页面，把含韩文 / 英文的文本节点编号并收集成标注列表。

导出：`Maurice.createExtractor({ domUtils, constants, getOriginalText? })`。

方法：

| 方法 | 说明 |
| --- | --- |
| `extractAll(pageId, options?)` | 返回 `{ annotations, stats }`；可传 `allocateTextId({type,text})` 使用稳定编号 |
| `toStoredEntries(annotations)` | 去掉 DOM 引用，转成可写入存储的纯数据 |

`extractAll` 流程：

1. `domUtils.resetVisibilityCache()`；
2. 遍历 `document.body` 下所有文本节点；
3. 用 `getOriginalText(node)` 取原文（页面已翻译时也不会拿到中文），再 `cleanText`；为空则跳过；
4. 不含韩文也不含英文则跳过；
5. 调用 `allocateTextId({ type, text })` 取编号；没有传分配器时退回本次顺序编号；
6. 生成 `id = pageId + '-' + textId`，记录 `type`（`ui` / `code`）、`text`、`node`、`visible`；
7. 统计 `{ total, visible, hidden }`。

注意：

- 隐藏文本也会提取，只是没有几何位置、不画徽标；
- 已翻译过的节点通过 `getOriginalText` 取回原文，所以“应用翻译”后再提取仍能得到原来的韩文 / 英文；
- 应用层会传入 `page-registry.createIdAllocator()`，所以正常使用时编号不是每次从 1 重数，而是复用持久编号。

## 13.5 `src/selection.js`（新增）

**作用**：捕获页面文本选区（原生左键选择 + 右键拖动选择），并把选区映射到已提取的标注节点。

导出：`Maurice.createSelectionService({ constants })`。

内部状态：

- `lastRange`：最后一次非折叠的页面选区。点“查找”导致选区折叠时不会被清掉，所以按钮点击后还能用；
- `rightDrag`：右键拖动状态（起点、起点 Range、是否已移动）；
- `suppressContextMenu`：拖动结束后临时屏蔽右键菜单；
- `listeners`：选区变化订阅者。

`install()` 注册的监听：

| 事件 | 作用 |
| --- | --- |
| `selectionchange` | 记录新的非折叠选区；面板内选区忽略 |
| `mousedown`（捕获） | 左键点页面清掉旧选区；右键记录起点坐标 |
| `mousemove`（捕获） | 右键移动超过 4px 后，用 `caretRangeFromPoint` 实时扩展选区 |
| `mouseup`（捕获） | 结束右键拖动，确认选区，并短暂屏蔽右键菜单 |
| `contextmenu`（捕获） | 拖动产生选区时拦掉浏览器右键菜单 |
| `blur` | 窗口失焦时清理拖动状态 |

方法：

| 方法 | 说明 |
| --- | --- |
| `getCurrent()` | 返回 `{ range, text }` 或 `null`；点查找后仍可用最后一次有效选区 |
| `hasSelection()` | 是否真的有非空选区 |
| `clear()` | 放弃当前记录的选区（输入编号时会调用） |
| `onChange(listener)` | 订阅选区变化，返回取消订阅函数 |
| `matchAnnotations(range, annotations)` | 返回选区真正覆盖到的标注数组；只碰到边界不算 |

选区匹配规则：

- 用 `Range` 与每个标注文本节点的内容求交集；
- 交集里必须有非空白字符才算命中，避免相邻节点边界误判；
- 返回顺序与提取顺序一致（文档顺序）。

右键拖动：

- 在面板、输入框、`textarea`、`select`、`contentEditable` 上不会启动；
- 移动距离小于 `SELECTION_DRAG_THRESHOLD`（4px）时当普通右键，保留浏览器菜单；
- 超过阈值后才创建选区并拦截右键菜单；
- 左键拖动选择同样会被 `selectionchange` 捕获，所以两种方式都能用。

阈值和消息长度由 `constants` 控制：`SELECTION_FULL_HIGHLIGHT_MAX=2`、`SELECTION_PREVIEW_LENGTH`、`SELECTION_ID_LIST_LIMIT`。

- `run(action)`：统一 `try/catch`，成功显示返回消息，失败显示“出错：…”，最后 `update()`；

- `renderDictList()`：用 `app.getDicts()` 生成词库行，所有动态字符串走 `html.escape*`；
- `renderUploads()` / `refreshUploads()`：渲染“我的上传”及下载 / 删除按钮；
- `update()`：刷新标注按钮透明度、词库列表、我的上传列表；
- `setResult(text)`：写结果区；
- `show()` / `hide()` / `toggle()`：面板显隐；首次显示时调用 `app.ensureInitialServerFiles()` 自动下载/更新 001/002。

事件映射（`data-act`）：

`close`、`extract`、`show-badges`、`hide-badges`、`apply-all`、`clear-translated`、`find`、`save-global`、`save-page`、`del-trans`、`import-dict`、`import-table`、`download-server`、`refresh-uploads`、`export-all-dicts`、`export-pending`、`export-table`、`export-translated`、`export-json`。

另外：

- `[data-dict-load]`：词库行的“加载”，调用 `app.loadDictAlone`；
- `[data-dict-upload]`：本地词库“上传”，调用 `app.uploadDict`；
- `[data-dict-progress]`：001/002 的“查询进度”，调用 `app.queryProgress`；
- `[data-dict-export]` / `[data-dict-del]` 是词库行内按钮，优先于通用按钮处理；
- `[data-dict-toggle]` 改变时调用 `app.toggleDict`；
- 文件输入 `change` 后调用 `app.importFile`（JSON 词库或 TSV 对照表），并在 `finally` 里清空，允许重复选同一个文件；
- 查找框输入时调用 `app.clearSelection()`，避免旧选区抢先生效；
- `selectionchange` 时如果页面上有了新选区，自动清空查找框，让“查找”按选区走。

`doFind()` 把输入框原值交给 `app.find()`：有编号按编号查，留空按选区查；返回 `source` 时回填原文 / 译文。

## 27. 数据流

### 启动

```
content.js
  → 创建服务
  → selection.install()          监听左右键选区
  → app.init()
      → ensureBase()
          → storage.load()
          → 生成/读取 clientId
          → dictionary.init()    确保 custom 词库
      → page-registry.resolvePageId()
      → translator.rebuild/apply 把已有词库写到页面
      → page-registry.createIdAllocator()
      → extractor.extractAll()   按持久编号收集当前文本备用
      → translator.startObserver() 监听动态内容
```

面板首次打开：

```
panel.show()
  → app.ensureInitialServerFiles()
      → 下载/更新 001 / 002（比较 serverUpdatedAt）
      → dictionary.installServerFile(activate=false)
      → update() 显示为未勾选
```

### 提取

```
点“提取并保存”
  → storage.load()
  → page-registry.resolvePageId()
  → page-registry.createIdAllocator()
  → extractor.extractAll(pageId, { allocateTextId })
  → page-registry.recordPage()     保存快照 + textIdMap
  → badge-layer.render()           画 P?-?? 徽标
  → 面板显示“共提取 N 条”
```

### 翻译

```
词库变化（保存 / 导入 / 勾选 / 单独加载）
  → dictionary 写入 storage
  → translator.rebuild()
  → translator.apply()
      → 遍历文本节点
      → 优先用 nodeStates.original 作为原文
      → dictionary.lookupExact()
      → pattern-rules 匹配动态数字
      → 已翻译节点原地更新，新节点写入译文，无译文则恢复原文
```

### 清除页面译文

```
点“清除译文”
  → translator.clearApplied()
  → 遍历 nodeStates，把 applied 过的节点写回 original
  → 清空节点状态（词库不动）
  → 面板显示恢复数量
```

### 对照表导入 / 导出

```
导出全部（可编辑）
  → storage.load()
  → text-table.buildAll()        原文 / 编号 / 译文，未翻译=暂无
  → transfer.downloadFile(文本对照表.tsv)

导入对照表（文件输入）
  → transfer.readTextFile()
  → text-table.parse()
  → dictionary.applyTable(rows)  写入“导入对照表”，置为最高优先级
  → translator.apply()           页面原地更新
```

### 导出

```
exporters.exportTable() / exportTranslated()
  → storage.load()
  → text-table 拼内容
  → transfer.downloadFile(文本对照表.tsv / 已翻译文本.tsv)

exporters.exportAll() / exportPending() / exportMerged() / exportSingleDict()
  → storage.load()
  → export-builders / dictionary 拼内容
  → transfer.downloadFile()
```

### 共享服务器

```
下载编号 / 上传 / 查询进度 / 我的上传
  → app.xxx()
  → server-api.js request()
  → chrome.runtime.sendMessage({type:'maurice-api', method, path, body})
  → background.js fetch(API_BASE + path)
  → 服务器 maurice-api.php（SQLite）
  → 返回 JSON
  → dictionary.installServerFile() / attachServerCode() / 结果消息
```

安装服务器词库默认 `activate=false`，所以下载后只在列表里出现，不勾选、不参与翻译。

### 选区查找

```
在页面上选中文本（左键拖动 / 右键拖动）
  → selection 记录 Range
点“查找”（输入框留空）
  → app.find('')
  → finder.findSelection
  → selection.matchAnnotations(range, annotations)
      → 1～2 条：badges.highlightNodes()   高亮完整文本
      → 超过 2 条：badges.highlightRange() 只高亮选中的范围
  → 面板显示编号、原文和高亮说明
```

## 29. 边界约定（避免再次耦合）

1. **DOM 只出现在 `dom-utils`、`extractor`、`translator`、`badge-layer`、`selection`、`panel`、`panel-template`、`content`、`transfer`**；`app` 以下不拼 HTML。
2. **chrome.storage 只出现在 `storage.js`**；其它模块通过 `store`。
3. **面向用户的业务消息由 `app.js` / `finder.js` 生成**；`panel.js` 只负责显示。
4. **导出内容构造是纯函数**，不要在里面下载或读存储；可编辑对照表放在 `text-table.js`。
5. **选区模块只处理 Selection / Range**，不读词库、不拼面板 HTML。
6. **对照表解析 / 构造也是纯函数**，不要直接写词库；写词库统一走 `dictionary.applyTable()`。
7. **服务器 HTTP 请求只出现在 `background.js`**；content 侧统一走 `server-api.js`。
8. **新增模块必须登记到 manifest 的 `js` 数组**，加载顺序即依赖顺序；`background` 会自动读取，无需重复登记。
9. **页面文本拼 HTML 必须转义**（`html.js`）。
